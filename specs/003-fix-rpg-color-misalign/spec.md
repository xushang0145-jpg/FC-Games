# 功能规范: 修复 RPG 游戏颜色错位

**功能分支**: `003-fix-rpg-color-misalign`

**创建日期**: 2026-06-06

**状态**: 草案

**输入**: 用户描述: "游戏内rpg颜色错位"

## 澄清记录

### 会话 2026-06-06

- Q: 颜色错位的具体表现？ → A: 红蓝通道互换（角色肤色偏蓝紫、天空偏橙红、文字颜色异常）；绿色、白色、黑色无明显差异。

## 用户场景与测试 *(必填)*

### 用户故事 1 - RPG 游戏画面颜色正确渲染 (优先级: P1)

作为玩家，在游玩任意 RPG 类 NES 游戏（如"吞食天地"）时，我希望游戏画面颜色与实际 NES 主机输出一致，角色、场景、文字的颜色准确无误，以便获得正确的游戏体验。

**为何此优先级**: 颜色错位直接影响游戏可玩性和视觉体验。对于 RPG 游戏，颜色错误会导致无法区分不同角色/NPC，严重影响游戏进程。此为渲染核心问题，必须在其他功能之前修复。

**独立测试**: 加载任意 RPG 类 .nes ROM，进入游戏画面后目视对比画面颜色与实际 NES 主机画面（参考已知正确的截图或视频），确认角色肤色、场景色调、UI 文字颜色无异常偏色或错位。

**验收场景**:

1. **给定** 模拟器已加载 RPG 游戏 ROM（如"吞食天地"），**当** 用户投币并开始游戏，**则** 游戏画面中角色皮肤颜色与实际 NES 输出一致，无明显偏红/偏蓝/偏绿。
2. **给定** 模拟器正在运行 RPG 游戏，**当** 游戏画面包含多种颜色（文字、背景、角色精灵），**则** 所有颜色区域的颜色与实际 NES 输出一致，不存在某个颜色通道错位（如红色显示为蓝色）。
3. **给定** 模拟器已加载非 RPG 游戏 ROM（如"超级玛莉"），**当** 用户开始游戏，**则** 游戏画面颜色保持正确，不会因修复而引入新的颜色问题（回归验证）。

---

### 边缘情况

- 如果 jsnes 返回的帧缓冲格式与当前代码假设的格式不一致（例如 RGB 通道顺序不同），系统应正确处理。
- 不同 Mapper 类型的 ROM（MMC1、MMC3 等）应全部正确渲染颜色。
- PAL 制式 ROM 应使用正确的调色板（当前以 NTSC 为主，PAL 可单独处理或保持现状假定 NTSC）。
- 所有 80+ 款 ROM 的颜色渲染不受修复影响，不得引入新回归。

## 需求 *(必填)*

### 功能需求

- **FR-001**: 系统 MUST 修复帧缓冲到 Canvas ImageData 的颜色通道映射，确保红色（R）和蓝色（B）通道各自写入正确的 ImageData 字节位置（当前表现为 R/B 互换，绿色通道正常）。
- **FR-002**: 系统 MUST 保证所有 NES 游戏（不限于 RPG 类型）的颜色渲染与实际 NES PALETTE 一致。
- **FR-003**: 系统 MUST 在修复过程中保持稳定的 60 fps 渲染性能。
- **FR-004**: 系统 MUST 在颜色修复后通过现有 E2E 测试（`tests/e2e/game.spec.js`）中与画面相关的断言。

### 关键实体

- **帧缓冲 (Frame Buffer)**: jsnes 在每帧通过 `onFrame` 回调输出的 256×240 像素数组，每个像素为 24 位颜色值（0xRRGGBB 格式）。当前代码将其解包为 R、G、B 时，R 和 B 通道映射到了 ImageData 的错误字节位置。
- **ImageData**: Canvas 2D API 用于 `putImageData` 的图像数据，格式为 RGBA（每像素 4 字节，顺序 R→G→B→A）。修复需确保帧缓冲的 R/G/B 通道分别写入 ImageData 的第 0/1/2 字节。

## 成功标准 *(必填)*

### 可衡量结果

- **SC-001**: 修复后，游戏画面中原本偏蓝的红色区域（角色皮肤、红色 UI 元素）恢复为正红色，原本偏红的蓝色区域（天空、水域）恢复为正蓝色。绿色、白色、黑色等不受 R/B 互换影响的颜色保持与修复前一致。
- **SC-002**: 渲染帧率保持稳定 60 fps，修复前后的帧率无明显下降（差异 < 2 fps）。
- **SC-003**: 现有 E2E 测试全部通过，无新增失败用例。
- **SC-004**: 至少测试 3 款不同 Mapper 类型的 RPG ROM（如 MMC1、MMC3），颜色均正确无误。

## 假设

- jsnes v1.2.1 的 NTSC 调色板数据正确，只是宿主代码的颜色通道映射有误。
- 当前系统使用的 Canvas 2D API 和 ImageData 为标准 RGBA 格式，不需要额外处理色彩空间。
- 所有 ROM 均为 NTSC 制式（中国大陆常见的汉化 ROM 多为 NTSC）。
- 移动端浏览器与桌面端浏览器在 Canvas ImageData 格式上行为一致。
