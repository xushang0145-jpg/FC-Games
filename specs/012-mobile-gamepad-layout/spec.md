# 功能规范：移动端虚拟手柄按钮布局调整

**Feature Branch**: `012-mobile-gamepad-layout`

**Created**: 2026-06-07

**Status**: Draft

**Input**: 用户需求 "调整手柄按钮布局：十字键位置不动，功能键放中间，AB 放右边"

## 用户场景与测试 *(必填)*

### User Story 1 - 手柄按钮布局重排 (Priority: P1) 🎯 MVP

移动端虚拟手柄的按钮布局调整为更符合经典游戏控制器习惯的排列：左侧十字方向键、中间功能键（SELECT / START）、右侧 A / B 操作按钮。

**Why this priority**: 布局调整是移动端操作体验的核心优化，当前 AB 在中间、功能键在右边的布局不符合玩家习惯。

**Independent Test**: 移动设备打开游戏页 → 虚拟手柄从右到左依次为：AB 按钮 → 功能键 → 十字键（或反之从左到右）。可独立验证。

**Acceptance Scenarios**:

1. **Given** 移动设备打开游戏页，**When** 虚拟手柄可见，**Then** 按钮区域从左到右依次为：十字键、功能键（SELECT/START）、AB 按钮
2. **Given** 虚拟手柄已渲染，**When** 用户触摸任意按钮，**Then** 触摸响应与按钮位置一致（无偏移）

---

### Edge Cases

- 屏幕尺寸 < 360px：三个区域按比例缩小，不重叠、不溢出
- 横屏模式：按钮间距和 padding 适应更宽的屏幕
- 竖屏模式：按钮紧凑排列，不超出安全区域

## 功能需求 *(必填)*

- **FR-001**: 虚拟手柄 MUST 将功能键区域（Start/Select）放置在十字键与 AB 按钮之间
- **FR-002**: AB 按钮区域 MUST 放置在最右侧
- **FR-003**: 十字键区域 MUST 保持在最左侧，位置和尺寸不变
- **FR-004**: 触摸事件 MUST 在布局变更后正确映射到对应按钮
- **FR-005**: 小屏幕适配（<360px）MUST 保持三个区域按比例缩放

## 成功标准 *(必填)*

- **SC-001**: 布局变更为纯 CSS/HTML 顺序调整，不影响触摸响应性能
- **SC-002**: 三种屏幕尺寸下（常规、小屏、横屏）按钮均不重叠、不溢出
- **SC-003**: 所有现有虚拟手柄 E2E 测试在布局调整后通过

## 假设

- 仅调整 DOM 插入顺序，不改变按钮本身的外观和尺寸
- 基于 CSS flexbox 布局，修改 HTML 结构顺序即可完成重排
