# 功能规范：去掉投币相关操作，简化游戏启动流程

**Feature Branch**: `011-remove-coin-overlay`

**Created**: 2026-06-07

**Status**: Draft

**Input**: 用户需求 "去掉投币相关操作" — 从列表点击游戏后直接进入游戏页面，不再需要投币/开始弹窗操作

## 用户场景与测试 *(必填)*

### User Story 1 - 从列表直接进入游戏 (Priority: P1) 🎯 MVP

玩家在游戏列表页点击游戏卡片后，在当前标签页跳转到游戏详情页。ROM 加载完成后直接显示游戏初始画面（无需任何弹窗确认），玩家通过键盘直接操作游戏。

**Why this priority**: 这是整个改动的核心——消除投币弹窗这个不必要的中间步骤，让玩家从列表到游戏画面路径最短。

**Independent Test**: 列表页点击游戏卡片 → 跳转到 game.html → ROM 加载完毕直接显示游戏画面 → 玩家按键盘操作游戏。

**Acceptance Scenarios**:

1. **Given** 玩家在游戏列表页，**When** 点击任意游戏卡片，**Then** 在当前标签页跳转到游戏详情页（非新标签页）
2. **Given** 游戏详情页加载完成且 ROM 校验通过，**When** ROM 加载完毕，**Then** 画面直接开始渲染游戏初始画面，不显示投币/开始浮层
3. **Given** 游戏画面正在渲染，**When** 玩家首次按下键盘按键（如 Enter/Start），**Then** 音频正常初始化并开始播放
4. **Given** 游戏详情页加载完成，**When** ROM 校验失败，**Then** 显示错误面板并提供重试和返回列表选项

---

### User Story 2 - 首次按键激活音频 (Priority: P1)

游戏画面渲染不需要用户交互，但 Web Audio API 要求用户手势才能启动 AudioContext。首次用户按键时自动初始化音频。

**Why this priority**: 音频是游戏体验的必要组成部分，但受浏览器安全策略限制必须延迟到用户交互后初始化。

**Independent Test**: ROM 加载后画面渲染、音频无输出 → 用户按任意键 → 音频开始正常输出。

**Acceptance Scenarios**:

1. **Given** ROM 已加载、画面正在渲染但音频尚未初始化，**When** 用户按下任意键盘按键，**Then** 音频系统初始化并开始播放游戏声音
2. **Given** 音频已初始化，**When** 用户后续按键，**Then** 按键事件正常处理游戏操作，不再重复初始化音频

---

### Edge Cases

- 用户在 ROM 加载过程中按键：按键事件不触发音频初始化，仅 ROM 加载完成后首次按键才初始化音频
- ROM 加载失败后按键：不初始化音频（因为模拟器未进入 loaded 状态）
- 页面加载时 URL 缺少 rom 参数：直接显示错误，不渲染 Canvas 画面
- 浏览器不支持 Canvas 或 Web Audio API：显示不支持提示，不进行任何初始化
- 从游戏页返回列表页：通过顶栏"返回列表"按钮正常返回

## 功能需求 *(必填)*

- **FR-001**: 游戏列表页点击游戏卡片 MUST 使用 `window.location.href` 在当前标签页跳转（不再使用 `window.open` 新标签页）
- **FR-002**: 游戏详情页 MUST 移除 start-overlay 浮层的 HTML、CSS 和 JS 逻辑（投币按钮、开始按钮、游戏标题展示）
- **FR-003**: ROM 加载校验通过后 MUST 立即调用 `emulator.start()` 启动帧循环渲染游戏初始画面
- **FR-004**: 音频初始化 MUST 延迟到首次用户按键时执行（调用 `emulator.setupAudio()`），确保 AudioContext 在用户交互上下文中创建
- **FR-005**: 游戏标题 MUST 在顶栏中展示（替代原弹窗中的标题展示）
- **FR-006**: 游戏启动记录（`recordPlayHistory`）和埋点（`trackGameStart`）MUST 在 ROM 加载完成并启动帧循环后执行
- **FR-007**: 投币逻辑（Select + Start 的自动按键序列）MUST 完全移除，游戏通过键盘直接操作

## 成功标准 *(必填)*

- **SC-001**: 从列表页点击游戏卡片到游戏画面首次渲染的时间不超过 ROM 加载 + 首帧渲染时间（无额外弹窗延迟）
- **SC-002**: 游戏画面渲染维持在稳定 60 fps，不受改动影响
- **SC-003**: 首次按键到音频开始播放的延迟不超过 200ms
- **SC-004**: 所有现有按键操作（方向键、A/B、连发、Start/Select）在改动后正常工作
- **SC-005**: 虚拟手柄（移动端）在改动后正常工作

## 假设

- 大部分 FC 游戏不需要投币操作（投币是街机概念，NES 游戏直接按 Start 开始）
- 玩家已经通过列表页的详情浮层了解了按键操作（详情浮层在 002 功能中已实现）
- 从游戏页返回列表页使用顶栏按钮即可，不需要浏览器后退按钮支持
