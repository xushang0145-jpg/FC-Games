# 快速验证指南：FC 游戏合集

**Date**: 2026-06-04 | **关联方案**: [plan.md](./plan.md)

## 前提条件

- Node.js 18+
- 已安装依赖：`npm install`
- ROM 文件存在于 `roms/` 目录

## 启动开发服务器

```bash
npm run dev
```

打开浏览器访问 `http://localhost:5173`（列表页）。

## 验证场景

### 场景 1：列表页渲染与浏览（P1-验收 1）

1. 打开 `http://localhost:5173`
2. 确认页面显示平铺网格布局的游戏卡片
3. 确认卡片数量 ≥ 80（对应 ROM 目录中的 `.nes` 文件）
4. 确认每张卡片显示游戏中文名称
5. 滚动列表，确认布局平稳无抖动

### 场景 2：打开游戏（P1-验收 2）

1. 在列表页点击任意游戏卡片（如"超级玛莉"）
2. 确认在新浏览器标签页中打开 `game.html?rom=超级玛莉.nes`
3. 确认游戏页显示"投币"和"开始"按钮
4. 确认原列表页标签页保持不变

### 场景 3：启动游戏（P1-验收 3）

1. 在游戏页点击"投币"按钮
2. 确认游戏页响应（投币状态变化/音效）
3. 点击"开始"按钮
4. 确认 Canvas 开始渲染游戏画面（稳定流畅，无明显掉帧）
5. 确认能听到游戏音频

### 场景 4：默认按键操作（P1-验收 4）

1. 游戏运行后，按方向键确认角色/光标移动
2. 按 Z 键确认 A 按钮功能（通常是跳跃/攻击）
3. 按 X 键确认 B 按钮功能
4. 按 Enter 确认 Start 暂停/菜单功能

### 场景 5：搜索过滤（P3）

1. 在列表页搜索框输入"超级"
2. 确认列表仅显示名称包含"超级"的游戏
3. 清空搜索框，确认恢复全部游戏
4. 输入不存在游戏的关键词，确认显示"没有找到匹配的游戏"

### 场景 6：自定义按键（P2）

1. 在游戏页点击按键设置按钮
2. 将"上"方向映射修改为 W 键
3. 保存设置
4. 确认游戏中按 W 键响应"上"操作，原 ArrowUp 不再响应
5. 关闭游戏标签页，重新从列表页打开同一款游戏
6. 确认之前的按键配置已自动加载

### 场景 7：错误处理

1. 手动访问 `game.html?rom=不存在的游戏.nes`
2. 确认显示错误提示，提供"重试"和"返回列表"选项
3. 点击"重试"确认重新尝试加载
4. 点击"返回列表"确认跳回列表页

### 场景 8：资源释放

1. 打开任意游戏并启动
2. 关闭游戏标签页
3. 确认无控制台错误，无后台音频继续播放

## 预期性能指标

| 指标 | 目标 | 验证方式 |
| --- | --- | --- |
| 列表页首次渲染 | <2 秒 | Chrome DevTools Performance 录制 |
| ROM 加载到可玩 | <3 秒 | 从点击卡片到画面动起来计时 |
| 游戏帧率 | ≥59 fps | requestAnimationFrame 计数（60 秒窗口） |
| 搜索响应 | <200ms | 输入到列表更新延迟 |

## 单元测试

```bash
npx vitest run          # 运行所有单元测试
npx vitest              # watch 模式运行测试
```

## E2E 测试

```bash
npx playwright test                     # 运行所有 E2E 测试
npx playwright test tests/e2e/list.spec.js   # 仅列表页测试
npx playwright test tests/e2e/game.spec.js   # 仅游戏页测试
```
