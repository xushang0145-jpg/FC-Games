# 功能规范：FC 游戏合集

**Feature Branch**: `001-games-collection`

**Created**: 2026-06-04

**Status**: Draft

**Input**: 用户描述："做一个网页FC游戏集合，用户可以在网页上玩FC游戏。游戏列表以平铺形式展开，每个游戏占用一个矩形区域，点击游戏区域即可开始游戏。游戏流程：进入游戏 → 投币 → 开始，任何时候都可以自行设定游戏的操作按键。"

## Clarifications

### Session 2026-06-04

- Q: 点击游戏卡片后，游戏以什么方式打开？ → A: 新浏览器标签页打开（游戏列表页面保持在原标签页）。
- Q: "投币"是纯 UI 步骤还是映射到模拟器按键？ → A: 映射为 NES Select 按钮信号（点击"投币"时向模拟器发送一次 Select 按下/释放）。
- Q: 按键配置是全局共用还是按游戏独立保存？ → A: 按游戏独立保存（每款游戏可有自己的按键映射，首次打开时使用默认配置）。
- Q: 游戏卡片除了名称外，是否需要视觉图片？ → A: v1 仅显示游戏名称，卡片使用纯色背景 + 文字排版（不引入封面图片资源）。

## 用户场景与测试 *(必填)*

### 用户故事 1 - 浏览游戏合集并开始游戏 (优先级: P1)

玩家打开网站后，看到按平铺网格排列的游戏列表，每个游戏以矩形卡片展示其名称。玩家点击感兴趣的游戏卡片，经过启动确认后进入游戏画面，使用默认键盘按键操作角色。

**为什么是这个优先级**: 这是整个功能的核心——没有这个流程，后续所有功能都无从谈起。该故事完成后即可独立向用户演示"选游戏→玩游戏"的完整链路。

**独立测试**: 从浏览器打开页面，点击任意游戏卡片，验证游戏能加载运行且键盘操控响应正常。

**验收场景**:

1. **Given** 玩家首次打开网页，**When** 页面加载完成，**Then** 显示平铺网格布局的游戏列表，每个游戏以矩形卡片呈现，卡片上标注游戏名称。
2. **Given** 游戏列表已展示，**When** 玩家点击某个游戏卡片，**Then** 在新浏览器标签页中打开该游戏的启动确认界面（含投币提示），原列表标签页保持不变。
3. **Given** 游戏启动确认界面已显示，**When** 玩家确认启动（投币 → 开始），**Then** 游戏开始运行，画面以稳定 60 fps 渲染，音频同步播放。
4. **Given** 游戏正在运行，**When** 玩家使用键盘默认按键（方向键控制移动，Z/X 键控制 A/B 按钮，Enter 为 Start，Shift 为 Select），**Then** 游戏角色响应相应操作。
5. **Given** 游戏加载 ROM 文件，**When** 加载完成，**Then** 从点击游戏卡片到游戏首次可玩的时间不超过 3 秒。

---

### 用户故事 2 - 自定义按键设置 (优先级: P2)

玩家进入游戏后或游戏开始前，可以打开按键设置面板，将每个游戏操作（方向、A/B 按钮、Start、Select）重新映射到自己习惯的按键上（例如 WASD 控制方向，空格键跳跃）。

**为什么是这个优先级**: 按键偏好因人而异，但默认按键已能让所有游戏可玩。自定义按键是提升舒适度的关键功能，在核心流程完成后优先实现。

**独立测试**: 打开按键设置面板，修改方向键映射为 WASD、A 按钮映射为空格，保存后返回游戏，验证新按键生效、已取消的默认按键不再响应。

**验收场景**:

1. **Given** 玩家在游戏页面中，**When** 玩家打开按键设置，**Then** 显示当前按键映射表，每个操作显示对应的当前按键。
2. **Given** 按键设置面板已打开，**When** 玩家点击某个操作并按下新按键，**Then** 该操作映射更新为新按键，如果新按键与其他操作冲突则给出提示。
3. **Given** 按键映射已修改，**When** 玩家保存设置并返回游戏，**Then** 游戏操作仅响应新映射的按键，原有默认按键不再生效。
4. **Given** 玩家之前为某款游戏保存过自定义按键，**When** 玩家再次打开该游戏，**Then** 自动加载该游戏上次保存的按键配置；打开其他未配置过的游戏时使用默认按键。

---

### 用户故事 3 - 游戏合集浏览增强 (优先级: P3)

玩家可以按游戏名称搜索筛选游戏，快速找到想玩的游戏。

**为什么是这个优先级**: 有 88 款游戏的合集中，纯滚动查找效率低。搜索功能是浏览体验的自然延伸，但不影响玩游戏的核心价值。

**独立测试**: 在游戏列表页面输入搜索关键词，验证列表实时过滤；验证无匹配结果时的友好提示。

**验收场景**:

1. **Given** 游戏列表页面已加载，**When** 玩家在搜索框中输入游戏名称关键词，**Then** 游戏列表实时过滤，仅显示匹配的游戏卡片。
2. **Given** 玩家输入的关键词无匹配游戏，**When** 过滤完成后，**Then** 显示"没有找到匹配的游戏"的友好提示。
3. **Given** 玩家在搜索结果中，**When** 玩家清空搜索框，**Then** 恢复显示全部游戏列表。

---

### 边界条件

- 当 ROM 文件加载失败时（网络错误或文件损坏），显示错误提示但不影响页面其他功能，玩家可尝试重新加载或返回列表。
- 当玩家快速连续点击同一游戏卡片时，防止重复创建多个游戏实例。
- 当浏览器不支持 Web Audio API 或 Canvas API 时，显示提示告知玩家当前浏览器不支持游戏功能。
- 当玩家关闭游戏标签页时，自动释放模拟器资源（停止帧循环、关闭音频）。
- 当按键设置中两个操作被映射到同一按键时，给出明确的冲突提示并阻止保存。

## 需求 *(必填)*

### 功能性需求

- **FR-001**: 系统 MUST 以平铺网格布局展示 `roms/` 目录下所有 `.nes` 文件的游戏列表，每款游戏以矩形卡片呈现，卡片上显示游戏名称。v1 卡片使用纯色背景 + 文字排版，不依赖外部图片资源。
- **FR-002**: 系统 MUST 在玩家点击游戏卡片后，在新浏览器标签页中打开该游戏的启动确认界面，包含"投币"和"开始"操作入口。
- **FR-003**: 系统 MUST 使用 jsnes 模拟器核心加载并运行玩家选择的 ROM，渲染画面到 Canvas，通过 AudioContext 输出音频。
- **FR-004**: 系统 MUST 提供默认键盘映射：方向键→方向、Z→A 按钮、X→B 按钮、Enter→Start、右 Shift→Select。
- **FR-005**: 玩家 MUST 能够在游戏运行前或运行中打开按键设置面板，为每项操作（上、下、左、右、A、B、Start、Select）重新绑定按键。
- **FR-006**: 按键设置 MUST 检测冲突：同一按键不能同时映射到两个不同操作，冲突时给出提示并阻止保存。
- **FR-007**: 玩家自定义的按键配置 MUST 按游戏独立持久化保存，下次打开同一款游戏时自动加载该游戏的配置；首次打开某游戏时使用默认按键映射。
- **FR-008**: 系统 MUST 在 ROM 加载失败时显示错误提示，并提供"重试"和"返回列表"两个操作选项。
- **FR-009**: 系统 MUST 在游戏标签页关闭时释放模拟器资源（停止 requestAnimationFrame 循环、关闭 AudioContext）。
- **FR-010**: 系统 MUST 提供搜索框，支持按游戏名称实时过滤游戏列表。
- **FR-011**: 系统 MUST 在检测到浏览器不支持必需 API（Canvas、Web Audio）时，显示不支持提示。
- **FR-012**: 系统 MUST 确保模拟器以稳定 60 fps 渲染游戏画面，不因游戏列表页面的复杂度而影响帧率。

### 关键实体

- **游戏 (Game)**: 代表一款 FC 游戏。关键属性：名称（从 ROM 文件名提取）、ROM 文件路径、显示名称。与 ROM 文件一对一对应。
- **玩家按键配置 (KeyBinding)**: 代表玩家对某款游戏操作按键的自定义映射。关键属性：关联的游戏标识、操作类型→键位代码的映射（上/下/左/右/A/B/Start/Select 共 8 项）。每款游戏最多一套配置。
- **模拟器会话 (EmulatorSession)**: 代表一个正在运行的游戏实例。关键属性：关联的游戏、jsnes 引擎实例、运行状态（运行中/暂停/已释放）。

## 成功标准 *(必填)*

### 可衡量成果

- **SC-001**: 玩家从打开页面到开始玩任意游戏的总操作时间不超过 15 秒（打开页面→浏览列表→点击游戏→启动→游戏可玩）。
- **SC-002**: 游戏运行时保持稳定 60 fps 渲染，在 5 分钟连续游戏过程中不掉帧（帧率不低于 59 fps）。
- **SC-003**: ROM 加载完成后首次可玩时间不超过 3 秒。
- **SC-004**: 玩家完成按键自定义设置的操作流程不超过 30 秒（打开设置→修改映射→保存→验证）。
- **SC-005**: 88 款游戏的列表页面在 2 秒内完成渲染并可用交互。
- **SC-006**: 玩家能在 5 秒内通过搜索找到目标游戏。

## 假设

- 玩家使用桌面端现代浏览器（Chrome、Firefox、Safari、Edge 最近 2 个主版本），具备 Canvas 和 Web Audio API 支持。
- 所有 ROM 文件均为合法有效的 `.nes` 格式文件，存放于 `roms/` 目录。
- 游戏名称为 ROM 文件名去除 `.nes` 扩展名后的中文名称。
- "投币"操作向 NES 模拟器发送一次 Select 按钮信号（按下/释放），模拟街机投币体验；"开始"操作发送一次 Start 按钮信号启动游戏。
- 默认按键映射选择大众熟悉的键位方案，以首次可玩为目标，不追求覆盖所有玩家偏好。
- 按键配置以浏览器本地存储方式持久化，不涉及服务器端存储。
- 移动端适配不在 v1 版本范围内（宪章规定桌面端优先）。
